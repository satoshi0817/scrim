# Scrim（0.1.0 build 8、ローカル開発版）

画面に Web / PDF / HTML パネルを重ねる macOS アプリ。旧名は Sheerpane。
bundle ID は `com.satoshi0817.Scrim`。公開・公証済みのリリースではありません。

## パネルの操作

表示と非表示は0.25秒のフェードです。フェード途中の再表示にも対応します。入力監視の取消などによる緊急非表示は即時です。

- 通常時はタイトルバーや操作メニューを表示せず、ページがパネル全体を使います。ページ内のクリック、入力、スクロール、戻る／進むジェスチャーは使えます。
- メニューバーの「レイアウトを編集…」から編集に入り、「完了」で戻ります。通常時の操作ボタン（HUD）は初期状態では非表示です。設定 → 一般 →「オーバーレイの操作ボタンを表示」で表示できます。Esc は編集中なら編集を終了し、通常の固定表示では0.5秒以内に2回連続で押すと閉じます。最初のEscはフォーカス中のWebアプリに届きます。設定 → 一般で1回押しに変更できます。Notionタスクの詳細ではEscで一覧に戻り、タスク名や本文の編集中は先に編集をキャンセルします。非表示・のぞき表示にすると編集を終了します。
- 編集時は枠が強調され、背景に横12列・縦8行のドットグリッドが出ます。画面端に16〜32pt、隣接するパネル間に8〜16ptの余白を画面サイズに合わせて確保します。パネルの中をドラッグして移動、端をドラッグしてサイズ変更します。編集時はページへの入力を止めます。
- 追加、複製、パネルを閉じる操作は編集時のみ可能です。Finder や「ファイルを開く…」から明示的にファイルを開いた場合は編集に入り、新しいパネルを追加します。
- 既存の保存配置は読み込みだけでは新しいグリッドに丸めません。編集に入ると現在の表示を余白付きグリッドへ揃え、移動・サイズ変更時も表示画面の分割に沿って配置します。近くのパネルには間隔を残して吸着します。

操作ボタンは macOS 26 以降で標準の `NSButton.bezelStyle = .glass` を使用します。外側の共通背景は設けず、ボタン自体を一層の Liquid Glass にします。macOS 14 / 15 では標準のボタン表現へフォールバックします。

「すべてのディスプレイで同じ配置」がオンの場合は、パネルの位置とサイズを画面に対する比率で維持します。小さい画面でも保存順で並べ直しません。パネルを前面に出す操作も位置に影響しません。

オフの場合、パネルの内容（追加・削除、URL、PC／スマホ表示）はページごとの共通リスト `panels` に保存し、ディスプレイごとの `layoutsByDisplay` には並び順と位置・サイズだけを保存します。配置を記憶していない画面では、共通の配置をその画面に対する比率で表示します。別の画面で追加したパネルは、共通の比率で末尾に加わります。どれかの画面で削除したパネルは、すべての画面の配置から取り除きます。

切り替えたときは直前の配置を引き継ぎます。オフにすると、すべての画面が共通の配置から始まります。オンに戻すと、`editedAt` が最も新しい画面の配置を共通の配置にします。`editedAt` を更新するのは、その画面でパネルを追加・削除したときと、位置・サイズを変えたときだけです。クリックでパネルが前面に出ただけの場合や、URLだけを保存した場合は更新しません。どちらに切り替えても、ディスプレイごとの配置は消去します。以前の版で画面ごとに別のパネルを置いていた場合は、起動時に一度だけ共通リストへまとめます（`displayContentShared`）。

「表示するディスプレイ」でオフにした画面は、キー `disabledDisplays` にUUIDで保存します。オフの画面にポインタがあるとき、ジェスチャーやショートカットでは開きません。メニューバーからの操作は、メインディスプレイかほかのオンの画面に表示します。すべての画面がオフでも、設定は開けます。UUIDを取得できない画面は記憶できないため、常にオンとして扱います。ノッチの予定タイマーはこの設定に従いません。

一時表示でもクリック・スクロールを使えます。設定 → 操作 →「一時表示中にクリック・スクロールを使う」で切り替えられ、初期値はオンです。キーを離すと閉じます。長押し中の⌘はScrim内のクリックから除外し、通常のクリックとして扱います。グローバルな入力や他アプリの操作は変更しません。

固定表示中は⌘,でレイアウト編集・設定・終了を選べます。編集中にパネルをクリックすると、そのパネルの設定がカードから画面中央へ広がります。左上にパネル名が表示され、設定や複製・削除などの操作は、上部のタブで切り替えます。設定は同時に1枚まで表示し、閉じるボタン・Esc・画面の余白のクリックで閉じられます。「視差効果を減らす」がオンのときはフェードで表示します。

パネルをホバーすると「クリックでメニュー · ドラッグで移動」のヒントが表示されます。4pt以上ドラッグするとパネルを移動できます。端から14pt以内では縦・横のサイズを変えられ、四隅の24pt四方では幅と高さを同時に変えられます。

## WebKit とログイン

表示には引き続き `WKWebView` を使います。通常のアプリ起動では永続化される既定の `WKWebsiteDataStore` を使います。
Webパネル・HTML・PDF・メモ・RTF・NotionタスクのWebリンクは、Macのデフォルトブラウザで開きます。別タブを指定したリンクにも適用されます。予定の会議・資料リンク、ノッチの参加ボタン、天気の出典も同じブラウザを使います。Slackのリンクも元のWeb URLを渡します。
ページ内の目次や、取り込んだHTMLの別ファイルへのリンクはパネル内で移動します。サイトが `window.open` で開くログインなどの別窓には、WebKitが用意した構成を使います。
Cookie、POST、リダイレクト、`window.opener` / `postMessage`、`window.close` に対応します。
ログインの別窓が残る間、元の WebView は休止によって破棄しません。オーバーレイを隠すと別窓も隠します。
JavaScript の alert / confirm / prompt は元のウィンドウにシートで表示します。

Notion Calendarの起動先は常に `https://calendar.notion.com/` を保存し、ログインの一時URLや日付付きの遷移先を再利用しません。既存の一時URLも起動時に正規化します。設定 → パネル → Webカレンダー →「表示するときに今日へ戻す」は初期値オンで、ページ側の「今日／Today」ボタンが準備できてから1回だけ押します。表示中は別の日に移動できます。編集中のパネルメニューから手動の「今日に戻す」も使えます。

対象は `calendar.notion.com`。公開配信コードは `window.open` と localStorage の `storage` イベントを使う認証フローを持ちます。対応する別窓、Cookie、storage 通知をローカル fixture で検証しています。実アカウントの認証完了は未確認です。サービス側の埋め込みブラウザ制限やパスキーの対応は別途確認が必要です。

## HTML・テキスト

「パネルを追加 → テキスト」で空のメモが開き、そのまま入力できます。追記するときは通常表示で本文をクリックします。上部のボタンで太字（⌘B）、下線（⌘U）、箇条書き、番号付きリストを選べます。複数行を選んでリストにすると、その段落にまとめて適用されます。Returnで次の項目に進み、空の項目で再度Returnを押すと本文に戻ります。

メモの文字サイズは、レイアウト編集中にメモをクリックして中央の「設定」タブから選べます。設定 → パネル →「文字サイズ」からも変更できます。極小・小・中・大・極大の5段階で、初期値は中です。表示倍率は全メモに適用し、保存した書式を保ちます。

本文と書式は `~/Library/Application Support/Scrim/PanelDocuments/` のパネルごとのフォルダにRTFで自動保存します。以前のメモは編集時に同じフォルダへ `note.rtf` を作成し、元の `note.txt` も残します。HTMLはレイアウト編集中にパネルをクリックし、「内容を編集…」を選ぶと変更できます。パネルを閉じた後もファイルは残ります。

Finderやファイル選択から開いたテキスト・Markdown・RTFは読み取り専用です。編集したいときはレイアウト編集中のパネルメニューで「メモとして複製」を選ぶと、自動保存されるコピーが開きます。Markdownの記号は原文どおりに表示します。

macOSの他社ウィジェットの埋め込みには対応していません。アプリ内の時計・カレンダー・天気は下記のネイティブパネルとして利用できます。

## HTMLファイルの取り込み

「パネルを追加 → HTMLファイルを取り込む…」で、HTMLをアプリ内へコピーできます。画像・CSS・JavaScriptなどがある場合は、それらをまとめたフォルダを選びます。フォルダ直下の `index.html` / `index.htm` / `index.xhtml` を優先し、なければ最初に表示するHTMLを選択します。取り込み後は元の場所に依存しません。

単体HTMLでは本体と、ブラウザ保存時の `*_files` / `*.files` フォルダを取り込みます。独自の `assets/` などがある場合はフォルダごと選択してください。隠しファイルとシンボリックリンクはコピーしません。取り込んだHTMLの読み取り許可は、そのパネル専用フォルダだけです。入れ子のHTMLも相対参照を保持し、元ファイルは変更しません。

## アプリ内ウィジェット

「パネルを追加 → ウィジェット」から次を追加できます。

- 東京の天気：気象庁の東京地方予報とアメダス東京観測点を使用。観測時刻、予報発表時刻、出典を表示します。10分間隔で取得し、通信失敗時は前回の情報またはエラーを表示します。位置情報の許可やAPIキーは不要です。
- 時計：端末のタイムゾーンで時刻と日付を表示します。
- 月間カレンダー：月の移動と「今日」への復帰が可能です。日付のカレンダーで、個人の予定やアカウントにはアクセスしません。

これらはSwiftUIのネイティブパネルで、macOSの他社ウィジェットをホストするものではありません。非表示中は更新タイマーと取得タスクを停止し、WebViewの4枚制限とは別に表示します。追加時のサイズは横2×縦1マスです。ギャラリーから直接ドラッグすると配置先の枠が現れ、既存パネルが移動・縮小します。ドロップで配置を保存します。

天気は [気象庁](https://www.jma.go.jp/bosai/forecast/#area_type=offices&area_code=130000) の公開データを利用します。現在の地域はユーザー指定の東京です。

## ウィジェットと次の予定

時計はレイアウト編集中、パネルのメニューから「アナログ時計／デジタル時計」を選んで切り替えます。通常表示ではメニューを隠し、時計だけを表示します。選択はパネルごとに保存・復元します。デジタルは時分と小さな秒を同じ行に表示し、タイムゾーンと日付を控えめに添えます。月間カレンダーの今日の日付はScrimのアクセントカラーで強調します。天気は内蔵パネル共通の背景色を使います。予報や天気記号は天候に応じて更新されます。「パネルを追加 → ウィジェット → 次の予定」で、Macのカレンダーに登録された今日を含めた指定日数の予定（初期値7日、進行中・終日・今日の終了済みを含む）を表示できます。カレンダーの色、予定名、時刻、場所を表示し、パネルの空きスペースに予定を並べ、残りはスクロールで確認できます。表示4件・取得8件の制限はなく、指定期間の取得件数を右上に表示します。

初回は「カレンダーを接続」を押してmacOSのアクセス許可を与えてください。予定の読み取りにはEventKitのフルアクセスが必要ですが、Scrimは予定を追加・変更・削除しません。予定を外部へ送信しません。許可を取り消した場合は接続案内に戻ります。表示中は1分ごととカレンダーの変更通知で更新し、非表示中は取得を停止します。実際のアカウントの予定表示は、ユーザーによる許可後の確認が必要です。

### 次の予定に表示するアカウント

開き直したときは、既定で「今の時間帯」へ移動します。進行中の時刻付き予定を優先し、なければ次の時刻付き予定へ移動します。対象がなければ今日の先頭へ戻ります。「設定 → パネル → 次の予定 → 開くたびに今の時間帯へ移動」をオフにすると、前回の位置を保ちます。表示中の更新や、一時表示から固定表示への切り替えでは位置を戻しません。「今日」「今の時間帯」ボタンで手動移動もできます。終了済みの予定も日付・時刻順を維持し、不透明度45%で表示します。

予定一覧の上部に、表示対象の予定から次のGoogle Meet／Zoom会議を選んで、会議名と残り時間を表示します。終日・開始済みの会議は対象外で、残り分は切り上げます。開始15分前からサマリーにも参加ボタンを表示します。カウントダウンは表示中に毎分更新します。

Google Meet／Zoomの参加リンクは予定カードに常に表示します。Meetは緑、Zoomは青のボタンで、ホバー時は指カーソルになります。その他のWebリンクとメモは「リンクとメモ」に初期状態で折りたたみ、クリックで展開できます。Notion、Google Docs、GitHubなどはサービスに応じた名前・アイコンを表示します。リンクは外部ブラウザへ開き、成功時にScrimを閉じます。メモはHTMLを読み込まずテキストとして表示し、リンク・メモの内容はログや設定へ保存しません。

レイアウト編集中に「次の予定」カードをクリックすると、画面中央で表示期間、除外キーワード、カレンダーを設定できます。アカウントごとのスイッチで一括選択でき、配下のカレンダーも個別に選べます。表示期間は今日を含めて1〜31日で、カレンダーの選択と一緒にパネルごとに保存します。

選択はパネルごとに保存し、再起動や複製でも引き継ぎます。カレンダーアプリやNotion Calendar側の表示チェックとは独立しています。初期状態は全カレンダーで、「すべて」で全選択、「選択を解除」で0件にできます。設定したカレンダーが削除・利用不可になっても、未選択のカレンダーへ自動的に切り替えません。レイアウト編集を終えると、設定面を閉じて予定表示へ戻ります。

### 除外キーワード

予定カードの編集メニュー →「表示するカレンダーを設定…」→「除外キーワード」で設定します。「キーワードを追加」で複数登録でき、入力欄で編集、ゴミ箱ボタンで削除できます。予定名にどれか1つでも含まれると非表示になります。部分一致で、英字の大文字・小文字や全角・半角は区別しません。空欄は無視します。編集はすぐに反映され、カレンダー選択・表示日数と一緒にパネルごとに保存します。予定そのものは削除しません。

### 短いダブルプレスから編集を開く

設定 → 操作 → ダブルプレス →「短く2回押すとレイアウト編集で開く」をオンにすると、⌘の2回目を短く離したときに直接編集モードへ入ります。初期値はオフです。2回目を長押ししている間の一時表示は従来どおりです。

### 日付ごとの予定表示

「今日の予定」「明日の予定」「○月○日の予定」という日付見出しで区切り、その下に時刻・予定名・場所を表示します。見出しには実際の日付と曜日も表示します。今日の予定がない場合もそのことを表示します。開始時刻は大きい丸みのある数字、終了時刻は控えめな小さい数字で表示し、開始まで1時間未満の時刻付き予定は赤い時刻・枠と「あと○分」のバッジで強調します。終日・進行中・終了済みはこの開始前の強調対象には含めません。進行中にはラベルを付け、今日の終了済みの予定は順序を保ったまま薄く表示します。終日・前日から続く予定にも対応します。

予定はカレンダーの色を薄く透過した角丸カードで表示し、淡いグラデーション・細い枠・控えめな影で統一しています。日付見出しと件数バッジは小さく整理し、参加ボタンは外部リンクの矢印を添えたピル型です。予定のURL・場所・メモにGoogle Meet／Zoomの参加リンクがあると「参加」ボタンを表示します。押すと既定の外部ブラウザで開き、Scrimを閉じてミーティング画面を表示しやすくします。予定データの変更や自動参加は行いません。

### 3時間ごとの天気予報

設定 → パネル → 天気 →「3時間ごとの予報を表示」でオン／オフできます。初期値はオンです。現在値と日別予報は気象庁のまま、3時間ごとの気温・天気・降雨確率はwttr.in / WorldWeatherOnlineを利用します。東京の予報を利用し、端末の位置情報は要求しません。横長で低いパネルでは左に現在の天気、右に時間別予報を並べます。時間別予報は横スクロールせず、幅に収まる件数（最大8件）を均等に表示します。出典を各欄に表示し、通信に失敗しても現在の天気や前回取得した情報を保持します。

### PC表示とスマホ表示

レイアウト編集中に対象パネルをクリックし、中央の「設定」タブでURLと表示モードを編集して保存します。PC表示は通常のMac用User-Agentとパネルいっぱいの幅、スマホ表示はiPhone用User-Agentと中央寄せの最大390ptの幅を使用します。選択したWebパネルに適用し、ローカルファイル・ネイティブウィジェットは変更しません。サイト側のスマホ対応によって見え方は異なります。

### 画面共有・スクリーンショット

設定 → 一般 → 画面キャプチャ →「画面共有・スクリーンショットから除外」は初期値オンです。前身NotchBrowserと同じ`NSWindow.sharingType = .none`を使い、オーバーレイ・設定画面・Webの別窓に適用します。オフにすると撮影を許可する指定へ戻します。

Appleは現在この値を旧式とし、キャプチャ防止に使わないよう説明しています。画面共有アプリの方式によってはScrimが映ります。この設定だけで非表示を保証しないため、実際の共有先で確認してください。Scrim自体を非表示にするモードではありません。[Apple公式](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)

## Notionタスク

ネイティブのタスク一覧です。Notion APIに直接接続し、サーバーは使いません。既存の「Notionビュー」（Webパネル）は変更せず、併存させます。

- **接続**：設定 → パネル →「Notion」に貼り付けた個人アクセストークンまたは内部接続のトークンを使います。保存先はキーチェーンの項目 `com.satoshi0817.Scrim.notion` / `notion-token` で、このMacだけに保存します（`ThisDeviceOnly`）。以前のアプリが使っていたキーチェーン項目は読み書きしません。NotionのOAuthはclient secretが必須でPKCEがないため、配布アプリには埋め込みません。トークンは全パネル共通です。個人アクセストークンは作成者が見られるものすべてにアクセスでき、「接続」の追加は要りません。ただし有効期限（7日〜1年、初期値1年）があり、切れると401になります。内部接続のトークンは、使うデータベースや作成先のページに接続を追加する必要があります。
- **API**：`Notion-Version: 2026-03-11`（2026-11-24時点の最新。ゴミ箱は `in_trash`、アーカイブは `is_archived` で、どちらも一覧から除外します）。データソース（`/v1/data_sources/{id}`）単位で読み書きします。一覧は `POST /v1/data_sources/{id}/query`、追加は `POST /v1/pages`（親は `data_source_id`）、完了・編集・取り消しは `PATCH /v1/pages/{id}` です。新規作成は `POST /v1/databases` で、選んだページの下に「タスク名（タイトル）」「完了（チェックボックス）」「期限（日付）」を作ります。
- **パネルURL**：`scrim-widget://notion-tasks?source=…&titleProp=…&doneType=checkbox|status&doneProp=…&doneOption=…&dueProp=…&name=…`。列は名前ではなくプロパティIDで保存するので、Notion側で列名を変えても動き続けます。パネルの内容なので、ディスプレイ別の配置でも全画面で共通です。
- **未完了の判定**：チェックボックスは `equals false`。ステータスは、完了にする値と同じグループに含まれる値（例：Completeグループの「完了」「中止」）を `does_not_equal` の `and` で除外します。期限の近い順（日付なしは作成順で後ろ）に並べ、1回の更新で最大200件まで読みます。
- **完了と取り消し**：チェックすると即座にNotionへ書き込み、4秒間は「元に戻す」で元の値（チェックなし、または完了前のステータス）に戻せます。その後、一覧から外します。
- **絞り込み**：読み込み済みの未完了タスクに対して、端末側で即座に絞り込みます（APIは呼びません）。文字はタスク名に対し、大文字・小文字、全角・半角、アクセントを区別せずに一致させます。期限（期限切れ・今日まで・今週まで・期限なし）、ステータス／セレクト／マルチセレクトの1列の値（いずれかに一致）、担当者（列の対応付けで選んだユーザー列。いずれかに一致）を組み合わせられます。この3つはパネルURLの `fdue`・`fprop`・`fval`・`fperson` に保存し、文字は保存しません。ステータスの選択肢には、完了グループの値を出しません。
- **タスクを開く**：一覧の行をクリックすると、パネル内に詳細を表示します。名前・期限・ステータスを変更でき、担当者とセレクト／マルチセレクトの値を表示します。本文は `GET /v1/blocks/{id}/children` をページ送りしながら読み、リスト・トグル・引用・コールアウトの子ブロックは3階層・合計400ブロックまで読みます（超えた分はNotionで開くよう案内します）。テキスト系ブロックのうち書式・リンク・メンションを含まないものだけを `PATCH /v1/blocks/{id}` で書き換えます。書式付きのブロックを書き換えると書式が消えるため、編集させません。ToDoのチェックは `{"to_do":{"checked":…}}`、追加は `PATCH /v1/blocks/{page}/children`（`position: {"type":"end"}`）、削除は `DELETE /v1/blocks/{id}`（ゴミ箱）です。2000文字を超える本文は、2000文字ごとのリッチテキストに分割して送ります。
- **文字サイズ**：レイアウト編集中にNotionタスクパネルをクリックし、「文字サイズ」タブで極小・小・中・大・極大を選べます。設定 → パネル →「文字サイズ」でも変更できます。タスク名は11／13／15／17／20pt、期限などは10／11／12／13／15pt、本文は11／13／14／16／18ptです。初期値は中で、選択は全Notionタスクパネルに適用します。
- **更新**：表示中のみ1分ごと。非表示の間は通信しません。429・5xxは1回だけ `Retry-After`（最大10秒）待って再送します。重複を避けるため、タスクの追加は再送しません。
- **エラー表示**：401はトークンの再登録、403は接続の機能（読み取り・挿入・更新）、404は接続の追加方法を案内します。列が消えたり型が変わったりした場合は、パネル内の「設定」から対応付けをやり直します。
- **URL・IDでの指定**：設定画面で、データベースのURL（notion.so、notion.site、app.notion.com、notion://。`?v=` のビュー付きも可）や32桁のIDを貼り付けられます。`NotionLink.objectID` がパスからIDを取り出し、`GET /v1/databases/{id}` でデータソースを取得します。データソースが1つならそのまま列の対応付けへ進み、複数なら選択肢を表示します。データベースが見つからない（404）か、ページだった（400）ときは、データソースIDとして `GET /v1/data_sources/{id}` を試します（Notionの「データソースIDをコピー」に対応）。Notion以外のURLは、通信せずに断ります。
- **検証**：`scripts/notion-fixture.py` は、使うエンドポイントだけを再現した合成データのローカルサーバーです（実アカウントなし）。`--verify-notion-tasks` は、メモリ上のトークンでパネルのモデルと設定画面を動かします。キーチェーンやapi.notion.comには触れません。実際のNotionワークスペースでの確認は未実施です。

## メモリ

2026-11-24の計測（releaseビルド、ウィジェット4種とWebパネル1枚）では、表示中・非表示ともに約54MBでした。編集中に全パネルへホバーすると204MB（うちIOSurface 115MB）になっていたため、次のように直しました。

- **ホバー時のぼかし**：パネルの静止画を1/4解像度で撮り、CPUのCore Imageでぼかします。ぼかしが消えたら画像を解放します。直した後は、全パネルへホバーして84MB、ホバー終了後は60MBです（IOSurfaceは9MB）。
- **非表示時のWebページ解放**：非表示のまま10分たつと、`OverlayController.releaseWebPanels` がWebページを解放します。システムのメモリ不足通知（warning／critical）では、非表示ならすぐに解放します。設定は `releasesIdleWebPanels`（初期値オン）で、次に表示したときに読み込み直します。ログイン用の別窓が開いているパネルは解放しません。
- **WebKitのプロセスを確実に終わらせる**：キーボードフォーカスを持ったことのあるWKWebViewは、AppKitのテキスト選択ジェスチャー追跡（`_NSTextSelectionTouchTracker`）が保持し続けます。ビューを外してもページが残り、WebContentプロセスが約300MBのまま残っていました。そこで、解放するビューは `BlankPageUnloader` で、取得しない別オリジン（`https://released.scrim.invalid/`）の空ページへ移します。読み込みは新しいプロセスで行われ、WebKitは古いプロセスを止めます。300MBを持つテストページで、古いプロセスが終了し、残りが約18MBになることを確認しました。待機させるとき、更新、URL変更、パネル削除、保持していたページの破棄でも同じ処理を通します。
- **ページ切り替え時の保持**：Webセッションを保持するのは、直前のページ1つ分です（以前は2つ）。
- **Notionタスクのモデル**：Notionタスクパネルのときだけ作ります（ほかのウィジェットではキーチェーンを読みません）。

## 設定画面

標準の設定用ツールバーで「一般」「操作」「パネル」を切り替え、SwiftUI の grouped Form で編集します。大きな独自ヘッダーは使わず、システム標準のフォント・色・スイッチ・ピッカー・開閉式の詳細設定を使います。

設定 → 一般 →「パネルの配色」では、ニュートラル・暖色・寒色の3テーマをライトとダークの見本で比較できます。「選択したテーマを編集」で、ライト・ダークそれぞれの背景とハイライトをカラーコード（#RRGGBB）またはRGBスライダーで調整できます。ハイライトには8色の候補もあります。変更はその場で内蔵パネルに反映し、テーマごとに保存します。見本には読みやすさを保つための明るさ・コントラスト補正を反映します。内蔵パネルの見出し・本文・補助情報には、共通のシステム書体と文字の太さを使います。

## 入力監視の復旧

2026-11-17 の ad-hoc 署名版では、再ビルドで署名のハッシュが変わり、TCC が以前の入力監視許可との不一致を報告しました。現在は証明書で署名し、コードを変えた再ビルドでも designated requirement が変わらないことを確認しています。

一度だけ、macOS のシステム設定 → プライバシーとセキュリティ → 入力監視で旧 Scrim を削除し、`/Applications/Scrim.app` を追加してオンにしてください。OS の許可はユーザー自身が操作します。アプリから TCC をリセットしたり直接書き換えたりしません。

設定の「操作 → 入力監視」は、許可と実際の監視を区別して表示します。「動作中」は有効なイベント監視に必要なイベント種類が揃っている状態です。許可後の接続、監視のタイムアウト、OS が監視を無効にした場合は最大1秒間隔で再接続します。再試行で権限要求は行いません。必要なら「再接続」でもやり直せます。

`--verify-input-monitoring` は偽の許可・監視を使い、許可前、許可後、権限取消、再許可、監視無効化、タイムアウト、再試行間隔、停止、CLI起動の隔離を検証します。実際のキーイベントを受けたことの証明には使いません。実機では別のアプリを前面にし、⌘の2回押しを確認してください。

## 設定の移行

Scrim の初回起動時だけ、Sheerpane → Chira の順で不足する設定をコピーします。
Scrim の既存値を優先し、旧ドメインへの書き込みはしません。Keychain には触れません。
旧アプリの WebKit データや入力監視の権限はコピーしません。
`SCRIM_DEFAULTS_SUITE` を指定した検証用起動は旧設定を読みません。
Scrim 用の新しいデザイン素材はローカルにないため、アイコン画像は以前のものを使っています。

```sh
rtk proxy swift build
```

旧 `build-sheerpane.sh` は新スクリプトへ転送します。
`swift test` には XCTest を含む Xcode が必要です。この Mac の Command Line Tools のみでは実行できません。
